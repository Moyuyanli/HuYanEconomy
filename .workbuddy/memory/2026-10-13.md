# 2026-10-13 工作日志

## 修复「IDEA 无法加载 Gradle 项目」（根因：私有 Nexus 不可达 + 仓库排在链首）

### 现象与取证
- IDEA 同步一直不结束；`jstack` 抓 `java.exe`（Gradle daemon pid 19012）：
  `Daemon worker` 卡在 `DefaultPluginRequestApplicator.applyPlugins`
  → `DefaultScriptClassPathResolver.resolveClassPath` → `HttpClientHelper.performHttpRequest`
  → `NioSocketImpl.timedFinishConnect`（建连阻塞）。
- `netstat -ano` 显示该 daemon 只有一条 `192.168.0.126:9281 -> 121.11.204.184:443 SYN_SENT`。
- DoH 解析：`nexus.chahuyun.cn` → **121.11.204.184**（广州电信），即卡的就是这个私有 Nexus。
- 用 `--info` + 短超时复现，拿到第一条失败资源：
  `com.github.gmazzo:gradle-buildconfig-plugin:3.1.0` 的 `.pom`
  → `Connect to nexus.chahuyun.cn:443 failed: Connect timed out`。

### 结论（关键机制）
- Gradle **只在 404 时**才继续试下一个仓库；遇到**连接超时/IO 失败会直接判定整个解析失败**。
- `nexus.chahuyun.cn` 同时排在 `pluginManagement` 和 `dependencyResolutionManagement` 的**链首**且**无分组限制**，
  于是任何第三方依赖（org.jetbrains.*、com.github.gmazzo.* …）都会先撞上它 → 同步长时间卡住。
- 本地缓存其实是**完整**的：
  - `./gradlew help --offline` ✅
  - `./gradlew :economy-main:dependencies --configuration compileClasspath --offline` ✅（含 cn.chahuyun 构件）
  - 临时 init 脚本把 nexus 摘掉后，联网 `help` ✅（依赖从 plugins.gradle.org / central 下载）

### 修复（`settings.gradle.kts`）
1. 公共仓库前置：`mavenCentral()` / `google()` / `gradlePluginPortal()` 排在私有 Nexus 之前。
2. 私有 Nexus 移到最后并加分组白名单：`content { includeGroup("cn.chahuyun") }`，
   非该分组的依赖再也不会去问它，坏掉也不阻塞构建。
3. 保留 `LocalOverflowGatewayStage` 文件仓库在最前（overflow-gateway SNAPSHOT 来源）。

### 验证
- `:economy-main:dependencies`（全部配置，含 overflow-gateway SNAPSHOT）→ BUILD SUCCESSFUL，日志中 `nexus.chahuyun.cn` 出现 **0** 次。
- `projects` + `:economy-main:dependencies --configuration testRuntimeClasspath` → BUILD SUCCESSFUL，同样 0 次。
- 附带发现：`cn.chahuyun:hibernate-plus:2.1.1`、`HuYanAuthorize-ksp:1.3.7` 在 Maven Central 也存在
  （日志出现 `Found locally available resource with matching checksum: [https://repo.maven.apache.org/...`），
  所以 Nexus 只是兜底，不是硬依赖。
