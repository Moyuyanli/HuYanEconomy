## 三代版本辨析（用户疑问：§11 是代码的 old/new 还是第三版？）

答案：**§11 是第三代**，与代码里任何一套 old/new 都不是同一个东西。
全仓共存在 **3 种互不相同的「版本/新旧」概念**，极易混淆：

| 代 | 位置 | Kotlin 类 | @Entity name | 表 | 状态 |
|---|---|---|---|---|---|
| 第一代 v1 | `entity/v1/fish/` | Fish / FishInfo / FishPond / FishRanking | Fish / FishPond / FishRanking | 无 hye_ 前缀 | **现网在用** |
| 第二代 v2 | `entity/v2/fish/` | FishEntity / FishInfoEntity / FishPondEntity | **带 V2 后缀**（FishEntityV2 等） | hye_fish / hye_fish_info / hye_fish_pond | **已接线**，`hye entity switch` 可切 |
| 第三代 §11 | `entity/fishing/` | FishEntity / UserPondEntity / UserFishingInfoEntity / FishingLogEntity | FishEntity / UserPondEntity / … | hye_fish / hye_user_pond / hye_user_fishing_info / hye_fishing_log | **未接线** |

另一条独立线索（不是实体版本）：
- `EconomyConfig.fishType: String by value("new")`（EconomyConfig.kt:41）—— 代码里另有一套
  `new/old` 开关，但**全仓无任何读取点**（只有 config.yml 里一行 `fishType: new`），从未生效。

命名陷阱（重要）：
- v2 与第三代都用 **Kotlin 类名 `FishEntity`**（不同包），但 `@Entity(name=…)` 不同
  （`FishEntityV2` vs `FishEntity`），所以 **Hibernate 实体名不冲突**。
- 真正的冲突在**表名**：v2 的 FishEntityV2 与第三代的 FishEntity **都映射 `hye_fish`**。
  另有 `hye_title_info`、`hye_user_backpack` 同样新旧同表。
- `entity/fish/`（注意无 ing）是**空目录残留**，可删。

其他文件核对：plan/ 中其余钓鱼提及均属**现网实现**的模块化/迁移记录
（manager-api.md 描述的是现有 FishManager API；模块化升级设计.md、临时整理路线.md 同理）；
docs/FAQ.md、docs/指令参考手册.md 描述的也是现网行为。无第二份新版钓鱼文档。
