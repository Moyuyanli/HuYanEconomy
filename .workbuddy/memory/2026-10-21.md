# 2026-10-21

## 经济后端布局改造：mirai 侧改为「单上下文 + scope 后缀」

### 决策（用户）

不再依赖 mirai-economy 的 `global()` 上下文。mirai 后端**始终只用 `custom(plugin)`**，
base 的 scope 用「自定义账户 id + 作用域后缀」实现。

原因：上游 context 是固定值集合（`global-economy` + 各插件 `plugin.id`），本质只有两个槽位，
base 想加第 5 个 scope 就无处安放。改成 id 编码后不再受上游结构限制。

### 编码规则（`ledger/MiraiAccountId.kt`）

| LedgerOwner | 上游 id | 上下文 |
| --- | --- | --- |
| `Wallet("u1")` | `u1`（无后缀） | custom |
| `UserBank("u1")` | `u1#BANK` | custom |
| `PluginAccount("p1")` | `p1#PLUGIN` | custom |
| `GlobalAccount("g1")` | `g1#GLOBAL` | custom |

- Wallet 不加后缀：存量钱包就在 `(custom, u<qq>)`，零搬迁
- 分隔符 `#`；解码取 lastIndexOf + 后缀白名单，账户名含 `#` 不会被截错
- 附带收益：`u999#PLUGIN` 不再匹配 `^u\d+$`，堵住插件账户名误用用户形态的命名空间风险

### 关键改动

- `MiraiEconomyLedger`：移除所有 `global()` 调用；新增 `Layout` 枚举（`SCOPE_SUFFIX` 运行时 /
  `LEGACY_CONTEXT` 仅迁移读）；`entries` 改为纯后缀分类，不再靠 `^u\d+$` 区分用户/自定义；
  `start()` 增加历史布局残留自检并 `Log.warning`
- `EconomyMigration`：`migrate` 源固定 `LEGACY_CONTEXT`，`exportBase` 目标 `SCOPE_SUFFIX`；
  `status` 分列两种布局。**旧布局余额只能经 base 中转一次**，不能上游对上游直改
- `LegacyEconomyApi.init()`：只注册货币，删掉 global 银行总额缓存 + 3 小时定时任务（新布局下无意义
  且启动即全量扫描）
- `AGENTS.md` 补一条约定

### 上游事实（解压 sources jar 确认，`D:\SYSTEM\TEMP\mec`）

- `custom(scope: CoroutineScope)` 内部 `plugin = scope as JvmPlugin`，`context = plugin.id` → 按插件隔离
- `global()` 的 `context = "global-economy"`
- 余额表 `economy_balance_record` 主键 `(uuid, context, currency)`（EmbeddedId `EconomyAccountIndex`）
- `economy_account_record` 主键只有 `uuid`，`description` 是可变的，会被 `merge` 覆盖
- **没有** transfer API，转账只能"先扣后加 + 补偿"

### 代价（已写进文档 §12.6）

1. 跨插件共享归零：`custom(plugin)` 使用 `plugin.id` 作 context，别的插件看不到这些余额
2. 其它 mirai-economy 生态插件按 `^u\d+$` 只能找到钱包，看不到 `#BANK` 等账户
3. 只有钱包位置不变，主银行/插件池/全局池都要搬，漏做 migrate 会显示余额归零（已有启动告警）

## 首个 feature 接入新经济接口：签到

### 新增 `economy-core/ledger/UserWallet.kt`

业务级钱包门面，`BigDecimal` 语义，构造可注入 `EconomyLedger`（默认 `EconomyLedgerProvider.current`）：

- `balance(qq)` / `credit(qq, amount, nickname)` / `debit(qq, amount, nickname)`，后两者返回 `LedgerOp`
- `credit` 成功时 `LedgerOp.balance` 就是入账后余额，签到回显直接复用，省一次查询
- companion：`money(Double|BigDecimal)` 两位 HALF_UP、`accountId(qq) = "u<qq>"`、`current()`

### 签到改动

- 步骤 5 入账：`EconomyUtil.plusMoneyToUser(user, gold)` → `UserWallet().credit(userInfo.qq, money(gold), userInfo.name)`
- 步骤 7 余额：复用 `credit.balance`，为空才 `wallet.balance(qq)`
- `SignOutcome.gold`：`Double` → `BigDecimal`；`SignRules.logCommitted` 用 `toPlainString()`
- 用 `userInfo.qq` 取代 `userInfo.user`：账本只要 `u<qq>` 字符串，去掉 mirai `User` 依赖后可在无
  mirai 运行时的测试里跑真实数据库
