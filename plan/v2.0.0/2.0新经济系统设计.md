# 2.0 新经济系统设计

## 1. 设计目标

2.0 经济系统不再依赖 `mirai-plugin-economy`（包括 `mirai-economy-core`），由本插件提供完整的本地账户、Scope、余额和经济操作实现。

经济系统作为独立模块 `economy-base` 存在：

- 自行维护经济实体、Repository、核心服务和操作 API。
- 不经过 `economy-data` 的 Entity Proxy。
- 与现有插件共用数据库连接配置。
- 旧 v1/v2 实体保留，不删除、不写入，仅用于历史查询、兼容和迁移。

## 2. 旧实体状态

`economy-data/entity/v1` 和 `economy-data/entity/v2` 中的实体统一标记为：

- `LEGACY`
- `READ-ONLY`
- 禁止新增业务写入
- 禁止新经济系统依赖
- 仅用于历史数据读取、迁移工具和兼容逻辑

新经济实体不得放入旧实体包，建议放在：

```text
cn.chahuyun.economy.base.entity
```

旧数据迁移是否执行、如何执行，属于独立迁移任务，不由新账户运行时自动完成。

## 3. 数据模型

### 3.1 Scope

Scope 是账户所属的业务域，不再使用账户表中的字符串字段表示。

```text
economy_scope
-------------
id          BIGINT AUTO_INCREMENT PRIMARY KEY
name        VARCHAR(64) NOT NULL
code        VARCHAR(16) NOT NULL UNIQUE
created_at  TIMESTAMP NOT NULL
updated_at  TIMESTAMP NOT NULL
```

初始化时必须创建系统默认 Scope：

```text
id   = 1
name = 默认
code = DEFAULT
```

`DEFAULT` 是系统保留 Scope，不允许删除或修改 code。

### 3.2 Account

```text
economy_account
---------------
id            BIGINT AUTO_INCREMENT PRIMARY KEY
account       VARCHAR(64) NOT NULL
scope_id      BIGINT NOT NULL
description   VARCHAR(255)
balance       DECIMAL(19,2) NOT NULL DEFAULT 0
update_time   TIMESTAMP NOT NULL
UNIQUE(account, scope_id)
FOREIGN KEY(scope_id) REFERENCES economy_scope(id)
```

说明：

- `id` 使用数据库自增 `BIGINT`，作为内部唯一主键。
- 账户身份由 `(account, scope_id)` 唯一确定。
- `description` 只用于描述、展示和日志，不参与账户身份。
- `balance` 最高保留两位小数。
- `update_time` 在每次成功修改账户后自动更新。
- Scope 外键使用 `RESTRICT` 语义，防止删除仍被使用的 Scope。

## 4. 账户编码

所有 `User`、`UserInfo` 的账户转换最终必须调用 `EconomyAccount.take`。

### 4.1 Mirai User

```text
个人默认账户：account = u<用户QQ>, scope = DEFAULT
群公共池：    account = g<群号>,   scope = DEFAULT
群内个人账户：account = u<用户QQ>g<群号>, scope = DEFAULT
```

群公共池与群内个人账户是不同概念：

- `g<群号>` 表示群公共资金池，群成员共享。
- `u<用户QQ>g<群号>` 表示某用户在指定群域中的独立账户。

账户字符串由统一工厂方法生成，业务代码不得自行拼接。

### 4.2 EconomyAccount

```kotlin
EconomyAccount.take(account: String, scope: EconomyScope? = null)
EconomyAccount.from(user: User)
EconomyAccount.from(userInfo: UserInfo)
```

`take` 的规则：

- scope 未提供时使用 `DEFAULT`。
- 账户不存在时创建，存在时从数据库加载。
- 创建和查询必须在事务中完成。
- 通过 `(account, scope_id)` 唯一约束处理并发创建。
- 对 account 做去空格、长度校验和格式规范化。

## 5. Scope API

```kotlin
EconomyAccount.scopeName(name: String): EconomyScope?
EconomyAccount.scope(code: String): EconomyScope?
EconomyAccount.scopeCreate(name: String, code: String): EconomyScope
EconomyAccount.scopeDelete(scope: EconomyScope): Boolean
```

删除规则：

- 只允许删除没有任何账户引用的 Scope。
- 只要存在一个账户使用该 Scope，就拒绝删除。
- 业务检查和删除必须在同一事务中执行。
- 数据库外键必须继续使用 `RESTRICT` 作为最终保护。
- `DEFAULT` Scope 永远不可删除。

## 6. EconomyCore

`EconomyCore` 是经济系统唯一的事务和并发边界，负责：

- 账户获取和转换
- Scope 获取、创建和删除
- 事务生命周期
- Session 生命周期
- 经济操作调度
- 结果封装

### 6.1 单操作单 Session

每个 EconomyCore 操作必须满足：

```text
一个操作 -> 一个事务 -> 一个 Session
```

具体要求：

- 一个操作内的 `take`、锁定、余额修改和提交使用同一个 Session。
- Session 不得跨线程或跨协程传递。
- Session 只能在创建它的操作上下文中使用。
- 操作完成后，无论成功或异常，都必须关闭 Session。
- 协程切换时不得把 Session 作为可共享状态保存。
- 业务层不直接持有 Session，Session 只在 EconomyCore 内部传递。

`hibernate-plus` 负责提供 SessionFactory 和 Session 获取能力；`EconomyCore` 负责将一次经济操作限制在单一事务和单一 Session 中。

### 6.2 并发安全

Hibernate 的 `SessionFactory` 可并发使用，但 `Session` 不可并发共享。并发安全由以下层次共同保证：

- hibernate-plus：每次事务使用独立 Session，异常自动回滚，结束自动关闭。
- EconomyCore：保证一个操作只使用一个 Session，禁止跨协程共享。
- 数据库：使用唯一约束、行级锁和原子条件更新。
- EconomyAction：不执行账户创建，只操作已存在账户。

扣款应使用条件更新或悲观锁，不能使用无锁的“读取余额后写回”。

## 7. EconomyAction

`EconomyAction` 只负责已存在账户之间的经济操作，不提供账户查询、创建或字符串解析。

```kotlin
EconomyAction.add(account: EconomyAccount, amount: EconomyBalance): EconomyActionResult
EconomyAction.subtract(account: EconomyAccount, amount: EconomyBalance): EconomyActionResult
EconomyAction.transfer(
    from: EconomyAccount,
    to: EconomyAccount,
    amount: EconomyBalance
): EconomyActionResult
```

所有 amount 必须是正数。Action 还需要拒绝：

- 空金额
- 超过两位小数的金额
- 超出 DECIMAL(19,2) 范围的金额
- 无效账户
- 同账户转账
- 余额不足

转账必须在一个事务内完成：

1. 按账户 ID 固定顺序锁定来源和目标账户。
2. 检查来源余额。
3. 扣除来源账户。
4. 增加目标账户。
5. 任一步失败则整体回滚。

## 8. 操作结果

返回值保持简化，但不能只有 Boolean：

```kotlin
enum class EconomyActionStatus {
    SUCCESS,
    INSUFFICIENT_BALANCE,
    INVALID_AMOUNT,
    SAME_ACCOUNT,
    FAILED
}

data class EconomyActionResult(
    val status: EconomyActionStatus,
    val balance: EconomyBalance? = null
) {
    val success: Boolean
        get() = status == EconomyActionStatus.SUCCESS
}
```

数据库异常、内部异常统一记录日志，并对外返回 `FAILED`，不暴露 Hibernate 或 SQL 异常细节。

## 9. 金额规范

数据库字段使用：

```text
DECIMAL(19,2)
```

业务层统一使用 `EconomyBalance` 表示金额和余额；数据库映射层使用 `BigDecimal`。

`EconomyBalance` 不能继承 `BigDecimal`、`Int` 或 `Long`：`Int`/`Long` 是不可继承的 Kotlin 数值类型，且金额不应通过多重数值继承实现。因此采用不可变封装类型，内部唯一存储值为 `BigDecimal`：

```kotlin
@JvmInline
value class EconomyBalance private constructor(
    val value: BigDecimal
) : Comparable<EconomyBalance> {

    companion object {
        fun of(value: BigDecimal): EconomyBalance
        fun of(value: Int): EconomyBalance
        fun of(value: Long): EconomyBalance
        fun of(value: Double): EconomyBalance
    }

    fun format(scale: Int = 2): String
    override fun compareTo(other: EconomyBalance): Int
}
```

`of(Int)`、`of(Long)` 和 `of(Double)` 只是便捷入口，进入类型后立即转换为 `BigDecimal`。核心计算、数据库读写和 Action 参数均使用 `EconomyBalance`，不使用 Double 参与实际计算。

提供必要的便捷重载：

```kotlin
add(account, amount: EconomyBalance)
add(account, amount: BigDecimal)
add(account, amount: Int)
add(account, amount: Long)
add(account, amount: Double)
```

所有重载进入核心层后必须立即转换为 `EconomyBalance`，并统一执行：

- 正数校验
- 两位小数校验或舍入
- 上限校验
- 统一舍入规则

`EconomyAccount.balance` 的类型为 `EconomyBalance`，操作和展示都使用该类型：

```kotlin
val balance: EconomyBalance = account.balance
balance.format()
balance.format(scale = 2)
```

格式化只用于展示，不改变数据库余额。`EconomyBalance` 应提供必要的比较、加减和正数校验能力，禁止暴露可变金额状态。

## 10. 数据库与 hibernate-plus

`economy-base` 与插件现有模块共用数据库连接配置，但经济账户实体由 `economy-base` 自行维护。

需要保证：

- 不创建不必要的第二套连接池。
- 同一个数据库上下文中的操作可复用同一 SessionFactory。
- `fromSession` 和 `fromTransaction` 的 Session 创建、关闭、提交和回滚行为明确。
- 经济操作可在一个 Lambda 事务中完成多个 Repository 操作。
- 不依赖 `current_session_context_class=thread` 来实现 Session 共享安全。
- 生产环境避免使用过低的 `READ_UNCOMMITTED` 隔离级别；账户操作优先使用原子更新或悲观锁。

## 11. 模块迁移

移除 `mirai-plugin-economy` 后需要清理：

- 各模块 Gradle 中的 `mirai-economy-core` 依赖。
- 插件主类中的上游插件依赖声明。
- `EconomyUtil`、`EconomyAccountService` 及其所有调用点。
- 私人银行、红包、基金、钓鱼、农场、抽奖、抢劫等模块中的上游账户调用。
- 相关测试和文档。

业务模块统一依赖 `economy-base`，不再直接访问上游经济 API。

## 12. 暂不纳入

本阶段暂不设计经济流水表。账户表只保存当前余额。

但操作描述、操作结果和事务边界必须保留，未来如果加入流水或幂等请求号，不应破坏现有 `EconomyAccount` 和 `EconomyAction` API。
