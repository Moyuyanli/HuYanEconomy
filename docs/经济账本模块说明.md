## 一、模块定位与边界

`ledger` 是 **infra 包**，不属于任何单个功能：签到、银行、私人银行、红包、农场、抢劫、
抽奖、钓鱼等 10+ 个功能都要读写余额，因此它留在 `feature/` 之外
（判据见《项目开发说明》§3.3.5）。

它承担三个职责：

| 职责 | 承载文件 | 说明 |
|------|----------|------|
| **唯一资金入口** | `EconomyProxy` | 业务只描述"位置 + 方向 + 金额" |
| **后端可切换** | `EconomyLedger` + `BaseLedger` + `MiraiEconomyLedger` + `EconomyLedgerProvider` | 本地账本（默认）或上游 mirai-economy |
| **上游隔离与迁移** | `LegacyEconomyApi` + `MiraiAccountId` + `MiraiEconomyProbe` + `EconomyMigration` | 上游类型只出现一处，旧数据可搬迁 |

**它不做什么**：

- 不做业务校验（"这人能不能付""账户是否冻结""是不是黑名单"）——属于各 feature 的 Rules；
- 不做流水审计——`economy_account` 只存余额，没有交易流水表；
- 不管余额展示文案——那是 `MessageBuilder` 的事。

**依赖方向**：`economy-base` 不认识 `economy-core`；`economy-core` 的 ledger 依赖
`economy-base` 的接口。业务（core 的 feature、game）只依赖 `economy-core` 的代理。

```text
feature/*  games/*           （业务：只说"谁、加减、多少钱"）
      │
      ▼
economy-core/ledger/EconomyProxy        ← 唯一入口 + 精度/编码收敛 + 后端注入
      │
      ▼
economy-base/ledger/EconomyLedger       ← 后端接口（契约）
      ├── BaseLedger                    （默认：本地 economy_account 表）
      └── MiraiEconomyLedger            （可选：上游 mirai-economy）
                │
                └── LegacyEconomyApi    ← 全项目唯一 import xyz.cssxsh.* 的地方
```

## 二、文件清单

`economy-base/base/ledger/`（3 个文件，接口与默认实现，零上游依赖）

| 文件 | 职责 |
|------|------|
| `EconomyLedger.kt` | 后端接口：`backendId` / `start` / `stop` / `balance` / `add` / `subtract` / `transfer` / `total` / `entries` + `adjust` 默认实现；错误码与实现约定写在类文档里 |
| `LedgerOwner.kt` | 位置模型 `LedgerOwner`（4 个子类型）、分类 `LedgerBook`、记录 `LedgerEntry`、结果 `LedgerOp` |
| `BaseLedger.kt` | 默认后端：位置 → Scope 映射、事务与悲观锁、异常兜底 |

`economy-core/ledger/`（7 个文件，代理、选择器、上游适配）

| 文件 | 职责 |
|------|------|
| `EconomyProxy.kt` | 业务唯一入口：四类位置构造 + `Account` 句柄 + `money`/`walletId` + `useBackend` 注入 |
| `EconomyLedgerProvider.kt` | 启动期按 `Config.yml` 选后端，探测/自检失败按开关降级 |
| `MiraiEconomyLedger.kt` | 上游后端：两种布局（`SCOPE_SUFFIX` / `LEGACY_CONTEXT`）、补偿式转账 |
| `MiraiAccountId.kt` | scope → id 后缀的编码/解码与分类判定（唯一编码规则所在地） |
| `MiraiEconomyProbe.kt` | 类存在性探测（`Class.forName(..., initialize = false)`） |
| `LegacyEconomyApi.kt` | 上游 API 封装 + 金币货币定义；41 个方法中仅 `init` / `economyService` / `CURRENCY_GOLD` 仍在用 |
| `EconomyMigration.kt` | 两套账本之间的一次性搬迁（`status` / `migrate` / `exportBase`） |

## 三、分层与依赖方向

| 层 | 内容 | 谁能调用 |
|----|------|----------|
| 业务层 | `feature/*`、`games/*` | 只能调 `EconomyProxy` |
| 代理层 | `EconomyProxy` + `Account` | 业务层、迁移命令 |
| 契约层 | `EconomyLedger` / `LedgerOwner` / `LedgerOp` | 代理层、两个实现、迁移 |
| 实现层 | `BaseLedger`、`MiraiEconomyLedger` | 只应由 `EconomyLedgerProvider` 实例化 |
| 适配层 | `LegacyEconomyApi` | 只允许 `MiraiEconomyLedger` 与 `MiraiEconomyProbe` |

三条禁止：

1. 业务层禁止 `import xyz.cssxsh.*`（`LedgerIsolationTest` 扫字节码常量池，白名单仅 3 个 ledger 文件）；
2. 业务层禁止直连 `EconomyAccount.take()` / `EconomyAccountService`（已删除）；
3. 除 `EconomyLedgerProvider` / `EconomyMigration` 外，不得自行 `new MiraiEconomyLedger(...)`。

## 四、启动与关闭时序

启动（`HuYanEconomy.onEnable`，顺序不可调换）：

| 步骤 | 调用 | 为什么在这个位置 |
|------|------|------------------|
| 1 | `HibernateUtil.init(this)` | 账本要读写 H2/MySQL，会话工厂必须先就绪 |
| 2 | `EconomyCore.init()` | 建 `DEFAULT` Scope、准备账户缓存 |
| 3 | `EntityProxyRegistry.init()` | 实体代理版本策略 |
| 4 | **`EconomyLedgerProvider.init()`** | 选后端并 `start()`：base 解析四个 Scope；mirai 注册货币 + 自检 + 旧布局残留告警 |
| 5 | 各 Manager `init()` | 它们会在初始化里读写余额（如发放存量奖励），必须晚于第 4 步 |

> 第 4 步失败的表现：`Config.yml` 选 `MIRAI_ECONOMY` 且 `economyBackendFallback=false` 时
> 插件**启动失败**并打印原因；开启降级时打 `error` 日志后回落 `BASE`。若 `BASE` 自身失败，
> 无论开关如何都抛错——账本不可用没有备胎。

关闭（`onDisable`）：先停业务（各 Manager `close/shutdown`），再 `EconomyLedgerProvider.shutdown()`，
最后停调度与异步池。`shutdown()` 会 `stop()` 当前后端并置空：`BaseLedger.stop()` 只清 Scope 缓存，
`MiraiEconomyLedger.stop()` 故意**不关闭上游服务**（上游由 mirai-economy 插件自己管，关掉会影响
其他插件）。

## 五、一次扣款的完整链路

以 `EconomyProxy.wallet(qq).debit(money(100.0))` 为例（base 后端）：

| # | 位置 | 动作 |
|---|------|------|
| 1 | `Account.debit(Double)` | 转调 `debit(money(100.0))`，两位 `HALF_UP` |
| 2 | `Account.debit(BigDecimal)` | 向 `EconomyProxy.backend` 取当前后端，调 `subtract` |
| 3 | `EconomyProxy.backend` | `injected ?: EconomyLedgerProvider.current` |
| 4 | `BaseLedger.subtract` | `runCatching { EconomyAction.subtract(account(owner), EconomyBalance.of(amount)) }` |
| 5 | `BaseLedger.account` | `EconomyAccount.take("u123456", Scope DEFAULT)`（不存在则建零余额账户） |
| 6 | `EconomyAction.subtract` → `EconomyCore.subtract` | 金额校验、余额下限校验、单事务写库 |
| 7 | `BaseLedger.toOp` | `EconomyActionResult` → `LedgerOp(success, balance, status.name)` |
| 8 | 业务 | 判断 `op.success`，失败按 `op.message` 给提示 |

mirai 后端在第 3 步之后分岔：`MiraiEconomyLedger.subtract` → `mutate` →
`resolve(owner)`（编码 id 与上下文）→ 上游 `account(...).minusAssign(...)`。

## 六、两套后端对照

| 维度 | `BaseLedger`（默认） | `MiraiEconomyLedger`（可选） |
|------|----------------------|------------------------------|
| 存储 | 本插件 `economy_account` + `economy_scope` | 上游 `economy_account_record` |
| 位置 → 账户 | 账户 id + Scope 表 | 账户 id（带 scope 后缀）+ 单一 `custom` 上下文 |
| 外部依赖 | 无 | 必须安装 mirai-economy-core |
| 事务 | 单事务，转账天然原子 | 无跨账户事务，转账靠补偿 |
| 余额下限 | 由 `EconomyCore` 保证不透支 | 取决于上游实现，本层不预检 |
| 全量枚举 | 一条 SQL（按 Scope 过滤） | 拉全量余额表在内存分桶 |
| 精度 | `DECIMAL(19,2)` | 上游 `Double` |
| 启动自检 | Scope 就绪 | 货币注册进 `basket` + 旧布局残留告警 |
| 失败表现 | `LedgerOp.fail(status.name)` | `LedgerOp.fail(错误码或异常 message)` |

**精度差异是本模块最需要注意的一点**：base 是两位小数定点，上游是 `Double`。
在 mirai 后端下，金额经 `BigDecimal → Double → BigDecimal` 往返，`0.1 + 0.2` 这类误差
会在上游侧累积；base 后端没有这个问题。需要严格对账的场景优先用 base。

## 七、账户编码规则

base 后端：`account` 列 `u<qq>` + `scope.code` 区分四类（`DEFAULT`/`BANK`/`PLUGIN`/`GLOBAL`）。

mirai 后端：上游账户坐标是 `(uuid, context)`，`context` 只有 `global-economy` 与各插件
`plugin.id` 两个固定值，**承载不了可自由新增的 scope**，所以把 scope 编码进 id：

| 位置 | 编码 | 上下文 |
|------|------|--------|
| `Wallet("u123456")` | `u123456` | `custom(plugin)` |
| `UserBank("u123456")` | `u123456#BANK` | `custom(plugin)` |
| `PluginAccount("prv_001")` | `prv_001#PLUGIN` | `custom(plugin)` |
| `GlobalAccount("bank_pool")` | `bank_pool#GLOBAL` | `custom(plugin)` |

三条约定：

1. **钱包不带后缀**——上游存量钱包就在 `(custom, u<qq>)`，同名可零搬迁；
2. **分隔符用 `#`**——QQ 号与既有插件账户名都不含该字符；
3. **解码取最后一个 `#` 并校验后缀白名单**——账户名自带 `#` 不会被截错，未知后缀整体当普通账户名。

附带效果：`Wallet` 分类额外要求 `^u\d+$`，因此历史裸自定义账户不会被误算进钱包；
`u999#PLUGIN` 也不再匹配用户形态。

新增 scope 时**只改 `MiraiAccountId` + `BaseLedger.scopeTable` + `LedgerBook`** 三处，
不要在业务里手拼后缀。

## 八、精度口径

| 环节 | 口径 |
|------|------|
| 入口 | `EconomyProxy.money()`：`BigDecimal.valueOf` + `setScale(2, HALF_UP)` |
| 传输 | 一律 `BigDecimal`，接口不提供 `Double` 重载 |
| base 存储 | `DECIMAL(19,2)`，上限 `99999999999999999.99` |
| 越界 | `INVALID_AMOUNT`，不静默截断 |
| 展示 | `balanceDouble()` 仅供格式化，超 2^53 会丢精度 |

历史包袱：2.0.1 之前的门面不做显式舍入，库里可能存在三位小数余额。首次经代理写入时会被
`HALF_UP` 截到两位——这是唯一一处**有损**变更，迁移前建议先跑一次对账。

## 九、并发与事务

| 场景 | base | mirai |
|------|------|-------|
| 单账户增减 | `fromTransaction` 内读改写 | 上游上下文锁 |
| 强制扣款（`adjust` 负数） | `PESSIMISTIC_WRITE` 行锁 | 同普通扣款 |
| 转账 | 两账户同事务 | 先扣后加 + 失败补偿 |
| 全量枚举 | 只读事务（`isDefaultReadOnly`） | 上游无事务，读到的是调用瞬间快照 |

**接口不承诺跨账户串行化**。组合操作（"先检查再扣款""扣 A 加 B"）需要调用方自己加业务锁
——参考农场、抢劫等玩法里的按用户/按群锁；不要指望代理层兜底。

`EconomyProxy` 的 `injected` 与 `EconomyLedgerProvider.ledger` 都是 `@Volatile`：
写入只发生在启动或测试装配的单线程阶段，读取方是任意业务线程。

## 十、类加载隔离约束

这是本模块最容易踩的坑，三条约束都有测试兜底：

1. **上游类只能出现在方法体内部**。`MiraiEconomyLedger` 的字段、父类、构造参数中出现
   `xyz.cssxsh.*` 类型时，未安装上游的环境在类解析阶段就会失败，抛的是
   `NoClassDefFoundError`（`Error`，`catch (e: Exception)` 接不住）。
2. **探测不能触发上游初始化**。`MiraiEconomyProbe` 用 `Class.forName(name, false, loader)`，
   且类名写成字符串常量——写成 Kotlin 类型引用，本文件就变成第二个上游依赖点。
3. **货币定义内联在 `LegacyEconomyApi`**。`GoldEconomyCurrency` 曾是独立类（`model/currency/`），
   为实现上游 `EconomyCurrency` 接口必须 import 上游；现在它是 `LegacyEconomyApi` 的
   `private` 嵌套类，全仓上游 import 只剩 `LegacyEconomyApi.kt` 一处。

验证方式：`LedgerIsolationTest` 扫描 `economy-core` main 产物**全部 class 常量池**，
白名单仅 `ledger/{LegacyEconomyApi, MiraiEconomyLedger, MiraiEconomyProbe}`；
另有断言要求 `LegacyEconomyApi.class` 确实含有上游引用（反向验证扫描器没瞎）。

## 十一、迁移与布局升级

两种布局（`MiraiEconomyLedger.Layout`）：

| 布局 | 钱包 | 主银行 | 插件/全局池 | 用途 |
|------|------|--------|-------------|------|
| `SCOPE_SUFFIX`（当前） | `custom` + `u<qq>` | `custom` + `u<qq>#BANK` | `#PLUGIN` / `#GLOBAL` | 运行时读写 |
| `LEGACY_CONTEXT`（≤2.0.1） | `custom` + `u<qq>` | `global` + `u<qq>` | 按上下文 | **仅迁移读取** |

迁移方向与命令：

| 命令 | 方向 | 幂等规则 |
|------|------|----------|
| `hye economy migrate` | mirai（历史布局）→ base | 目标余额非 0 跳过，可反复执行 |
| `hye economy export-base` | base → mirai（当前布局） | 沿用上游"累加"语义，不做非零检查 |

共同约束：单向、不删源数据、零余额跳过、负数照搬、`dryRun` 可预演。

切换后端的完整流程：

1. `hye economy status` 看两套账本家底 + 旧布局残留；
2. `hye economy migrate`（试运行）核对条目数与金额；
3. `hye economy migrate confirm` 真搬；
4. 改 `Config.yml` 的 `economyBackend: MIRAI_ECONOMY` 并**重启插件**；
5. 再 `hye economy status` 确认 mirai 侧金额一致，源数据留观一段时间后人工清理。

> 启动时 `MiraiEconomyLedger.start()` 会检查历史布局残留：仍有非零余额说明第 3 步没做，
> 此时读写会落在空账户上，日志会给 `warning` 提示。

## 十二、测试策略

`economy-core/src/test/kotlin/cn/chahuyun/economy/ledger/` 共 4 个文件、35 个用例：

| 文件 | 用例数 | 覆盖点 |
|------|--------|--------|

约定：

- 集成测试用 `EconomyProxy.useBackend(BaseLedger)` 显式注入，避免依赖 `Config.yml`；

- 所有用例跑在 H2 文件库上，不碰生产数据；`mirai-economy` 路径只测编码规则，不测真实上游。
- 跑单个类：`./gradlew.bat :economy-core:test --tests "*EconomyProxyH2Test*" --offline`。

## 十三、扩展指南

### 13.1 新增一类账户位置（scope）

1. `LedgerOwner` 加子类型；
2. `LedgerBook` 加分类；
3. `BaseLedger`：`scopeTable` 加 code、`scopeCode` 加映射、`scope()` 加 `when` 分支；
4. `MiraiAccountId`：加常量、加入 `SUFFIXES`、`encode`/`belongsTo` 加分支；
5. `EconomyProxy` 加构造方法（如 `fun pond(id: String): Account`）；
6. `EconomyMigration.owner()` 加映射（否则迁移会写错 Scope）；
7. 补 `MiraiAccountIdTest` 的编码用例。

### 13.2 新增一种经济后端

1. 在 `economy-base/ledger/` 或 `economy-core/ledger/` 实现 `EconomyLedger`，
   遵守《API 参考》§9 的契约（不抛异常、标准错误码、无状态句柄）；
2. 需要外部依赖时，参照 `MiraiEconomyProbe` 用字符串类名 + `initialize = false` 探测；
3. 在 `EconomyBackend` 加枚举值；
4. `EconomyLedgerProvider.candidate()` 加分支，保持"BASE 不降级、可选后端按开关降级"的规则；
5. 补迁移路径（`EconomyMigration`）与对账口径。

### 13.3 新增错误码

1. 实现里用 `LedgerOp.fail("NEW_CODE")`；
2. 同步《API 参考》§6 错误码表；
3. 同步 `EconomyLedger` 的"失败信息约定"表（两处表格必须一致，否则后人查不到）。

## 十四、已知技术债

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | `LegacyEconomyApi` 保留 39 个无调用方方法（约 780 行） | 阅读成本高，易被误用为"第二入口" | 确认迁移路径稳定后裁剪到 `init` / `economyService` / `CURRENCY_GOLD`，其余转入 `archive/` |
| 2 | mirai 后端 `debit` 不透支保证弱于 base | 贷款、竞拍类场景可能写出负余额 | 业务层先读余额 + 加锁，或统一使用 base 后端 |
| 3 | 两位小数截断历史三位余额 | 首次写入有损 | 迁移前跑对账，必要时先 `export-base` 备份 |
| 4 | mirai `entries` 每次全量拉余额表 | 排行榜、`status` 在账户多时变慢 | 需要时加短期缓存（注意跨进程一致性） |
| 5 | `EconomyMigration` 无分批/无断点 | 大账本中断需整体重跑 | 幂等规则已允许重跑；如需优化可按 `book` 分批 |
| 6 | mirai `LedgerEntry.description` 恒为 `null` | 上游展示名不可靠（会被覆盖） | 展示名从本地 `UserInfoDto` 取，不要依赖账本 |
